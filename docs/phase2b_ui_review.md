# UI確認 → 予習リストとして機能していない。修正8件

実際に abstract を貼って確認した。動作はするが使える状態ではない。
Phase 0 で決めた必須3項目のうち、機能しているのは出現文だけで、それも1語目のみ。
判定層に4周かけた分、表示層が遅れている。

## 1. 表示内容の修正(最重要)

共起語の羅列は判定の材料であって読者への説明ではない。
agility に対して digit, impressive, unprecedented と並べられても何も分からない。
以下の構造に変えろ。

デフォルト表示:
  - 語
  - この分野での意味(英語、短く)
  - 出現文(英語)

タップで開く:
  - 一般的な意味(日本語)
  - この分野での意味(日本語)

方針は Phase 0 のまま(日本語はデフォルト非表示)。トグルの粒度を語ごとにする。
狙いは、訳を見る前に自分で思い出す一拍を作ること。
分からない語だけ開けばよく、フラッシュカードのようにめくる操作は不要。
予習10〜15分の制約を壊さない。

「この分野での意味」を英語でデフォルト表示するのは、それ自体が読解のヒントに
なるため(curriculum に "gradually increasing task difficulty" とあれば
多くの場合それで足りる。日本語まで要るのは本当に詰まったときだけ)。

日本語の例:
  curriculum  一般: 教育課程 / 分野: 簡単な課題から段階的に難しくする学習方式
  disturbance 一般: 邪魔、妨害 / 分野: 外乱(制御対象に加わる予期しない入力)
  actor       一般: 俳優 / 分野: Actor-Critic の行動側。方策を出力するネットワーク

対比が一行で刺さることが最重要。正確さより分かりやすさを優先しろ。

共起語(一般の隣人 / この分野の隣人)はデフォルト非表示にしろ。
判定のデバッグには要るので設定で出せる形は残せ。

## 2. 出現文の表示(既存機能の不具合)

a. 1語目(agility)にしか表示されていない。以降の語には出ていない。
   全てのL3/L2語に出現文を表示しろ。

b. 文が途中で切れている。
   実例: "...sustaining speeds up to 3" で終わっている。
   おそらく "3 m/s" の数字トークンで文境界判定が誤っている。
   文分割ロジックを確認しろ。単位付き数値、小数点、et al.、Fig. 等の
   ピリオドで誤分割していないか。

c. 複数回出現する語(robot ×2 等)の扱いを決めろ。
   予習の速度を優先し、表示は1文でよい。
   ただしどの出現を選ぶかを決めること。推奨は「最初の出現」ではなく
   「その語の周辺に情報が多い文」だが、判定が複雑なら最初の出現でよい。
   選定基準を algorithm.md に記録しろ。

d. 長すぎる文は省略しろ。abstract の1文は長いことがあるので、
   語の前後を残して中略する形が読みやすいはず。実装は任せる。

## 3. 開閉のログを取れ

どの語を開いたかを記録しろ。ただし自動でステータスを変えるな。
「開かなかった=既知」とは限らない(読み飛ばしただけの可能性がある)。
記録は読了後チェックの参考値として使う。
読了後チェック画面で「開いた語」を優先的に確認対象に出せると効率がよい。
この連携を設計に含めろ。

## 4. 説明文の生成手段 —— (c)ハイブリッドへの移行を検討しろ

現状 senses.yaml の手キュレーションでは全語をカバーできない
(実測で大半が「語義未キュレーション」)。
Phase 0 の (a)完全静的では表示要件を満たせないことが実地で判明した。

提案を出せ:
- 判定は静的アルゴリズムのまま。この原則は絶対に変えるな
- 説明文の生成だけを LLM に任せる
- 生成した説明文はキャッシュして再利用しろ。同じ語を毎回生成するな。
  policy / attention のような頻出語は一度焼けば2本目以降のコストがゼロになる
- APIキーの扱い、コスト見積もり、オフライン時の挙動を含めること

提案を見てから実装を判断する。まだ実装するな。

## 5. 上限20が効いていない

38グループが全部表示されている。予習モードは上限20+もっと見る、と決めたはず。
実装漏れか設定か確認しろ。

## 6. 語幹グルーピングが効いていない

agility と agile が別グループになっている。
demonstration + demonstrate は確認済みとのことだったので、
レンマ表に載っていない変化形が素通りしている可能性が高い。
名詞派生(agile→agility, robust→robustness)が漏れていないか確認しろ。

## 7. 未照合率 55% について

半分以上の語が vocab_table に載っていない。これは正常か。
C コーパスの語彙カバレッジが薄いなら表示できる語が限られることになる。
原因を報告しろ。

## 8. 語の選定(優先度は低い。いま触るな)

agility / agile / turning / maneuver / fast / terrain / robot は
この論文の話題語であって危険語ではない。
一方 curriculum / disturbance / command は妥当。特に curriculum は本命
(カリキュラム学習。日常の意味で読むと確実に誤読する)。

ただしこれは既知の話題語混入問題なので、1〜7を直してから再評価する。
いま判定層に触るな。
