# USAGE — word-learning の使い方

想定読者: 3ヶ月後の自分。実装の説明ではなく使い方の説明。アルゴリズムや開発経緯は `ForNext_Report.md` と `docs/` の各文書にある。

---

## A. 動かす

3つの選択肢がある。**迷ったら 1**。

| # | 方法 | 必要なもの | 所要 | できること / できないこと |
|---|---|---|---|---|
| 1 | **デプロイ済みURLを開く** https://jun-jun0510.github.io/word-learning/ | ブラウザのみ | 0分 | 全機能使える。会社PC・スマホ向け。コードや語義データ(senses.yaml)の変更はできない |
| 2 | **cloneしてローカルで動かす** | Node.js ≥ 20.19 | 初回5分 | コード・語義データを直せる。直した結果を push すれば1が自動更新される |
| 3 | **何もしない**(既存の端末で続ける) | — | 0分 | 単語帳は端末ごとに別なので、同じ端末なら蓄積がそのまま残っている |

### 2 の手順(ローカル)

```bash
node --version        # v20.19 以上であること(推奨 v22)。無ければ nodejs.org から LTS を入れる
git clone https://github.com/Jun-Jun0510/word-learning.git
cd word-learning
npm install           # 初回のみ。1〜2分
npm run dev
```

成功すると以下が表示される:

```
  VITE v7.x  ready in ~300 ms
  ➜  Local:   http://localhost:5173/word-learning/
```

ブラウザで **http://localhost:5173/word-learning/** を開く(末尾の `/word-learning/` まで必要)。

よくある失敗:
- **Node が古い**(`npm install` や `npm run dev` が構文エラー等で落ちる)→ `node --version` を確認。v20.19 未満なら入れ直す
- **ポート5173が使用中** → vite が自動で 5174 等に切り替える。表示された Local の URL を開けばよい
- **画面が真っ白 / 「読み込み中…」のまま** → URL のパスが `/word-learning/` になっているか確認
- スマホで試す → `npm run dev -- --host` で起動し、表示される Network の URL を同一Wi-Fiから開く

## B. 使う(画面の順)

1. **予習タブ**で、読む論文の abstract(本文でも可)をテキスト欄に貼る
2. **「解析する」**を押す → L3 危険語 → L2 専門語 の順にリストが出る
3. **L3 から上から順に見る**。各語には「この分野での意味(英語)」と「実際の出現文(対象語は太字)」が出ている。英語の説明で分かればそれで十分
4. 分からない語だけ**行をタップ** → 一般(日本語)/ 分野(日本語)が開く。開く前に一拍、自分で思い出すのが狙い
5. すでに知っていた語は **known** を押す(赤 new → 黄 learning → 緑 known の順にタップで巡回)
6. 10〜15分で切り上げて**論文を読む**
7. 読み終わったら**読了後チェックタブ** → 文書を選ぶ → 各L3語を「読中に正しい分野の意味で読めていたか」で ○/× → 正答率が出る(目標80%)。「開」マークの語(予習で訳を開いた語)が先頭に来る

## C. 知っておくこと

- **2モードの使い分け**: 予習タブ=読む直前の10〜15分用(L3→L2のみ)。単語帳タブ=蓄積の閲覧・整理用(L1bも見える)。**予習に L1b(respectively 等の論文英語)が出ないのは、読む直前の時間を分野の危険語に集中させるため**
- **ステータス3値**: new=未対応 / learning=覚え中 / known=もう説明不要。**「次にこの語が出ても説明は要らない」と思えたら known**。known にした語は以後の予習リストから消える(単語帳には残る)— 使うほど予習が軽くなる仕組みの本体
- **「もっと見る」**: 予習リストは上位20グループまでしか表示していない。それより下にも語はある(消えてはいない)。リスト末尾のボタンで全展開できる
- **⚑とデバッグ表示**: 解析ボタン横のチェックを入れると、判定の内部情報(共起語、話題語疑いフラグ⚑)が見える。**普段は使わなくてよい**。⚑は精度が低いためデフォルト非表示にしてある

## D. データを守る(重要)

単語帳(ステータス・読了後チェックの記録)は**ブラウザの localStorage に端末ごとに保存**される。消えると全部無価値になるので、以下を守る。

- **エクスポート**: 画面右上「エクスポート」→ JSONファイルがダウンロードされる。**週1回、または論文を数本処理したら**実行する。ファイルは iCloud/Drive 等の消えない場所に置く
- **7日リマインドが出たら**: バナー内の「今すぐエクスポート」を押してファイルを保管する。それだけでよい(バナーは消える)
- **インポート**: 右上「インポート」→ バックアップJSONを選ぶ。**マージ動作**(置換ではない): 出典は和集合、ステータスは進んだ方(new < learning < known)が勝つ。復旧にも端末間の統合にも同じ操作でよい
- **端末ごとに単語帳は別**。PCとスマホ、自宅と会社で共有したい場合は「片方でエクスポート → もう片方でインポート」
- **消える経路**: iPhoneのSafariは**7日間サイトを開かないと**データを消すことがある。ブラウザの「終了時にデータを削除」設定やプライベートブラウズでも消える。エクスポートだけが保険

## E. 困ったとき

- **語義の説明が間違っている**(生成7,437語には誤りが混ざっている。conditioning で実例あり):
  - **選択肢1(デプロイ済みURL)で使っている場合**: その場では直せない。**「語 / 正しい意味 / 気づいた論文」を手元のメモに残す**(スマホのメモ帳・Slackの自分宛・紙、何でもよい。とにかくその場で書く — 後では思い出せない)。後で clone 済みの環境で下記の手順で直す
  - **clone 済みの環境での直し方**: `data/senses.yaml` を直接編集する。書式はファイル冒頭のコメントと既存エントリを真似る。編集後 `npm run build:stats` でローカル反映、commit & push すれば公開URLにも反映される。手書きは生成より常に優先される
  - ※UIからその場で修正できる導線は未実装(Phase 3 候補)。上記のメモ運用はその不在の実務上の帰結
- **出るはずの語が出てこない**: まず「もっと見る」で全展開して確認。それでも無ければ既知問題の可能性が高い — `ForNext_Report.md` §4(保留中の既知問題: Gaussian等の人名由来語の欠落、L1bの精度、ほか)を参照。判定層は凍結中なのでその場では直さず、メモして次の評価セットに回す
- **画面がおかしい・エラーが出る**: リロードで直ることが多い。直らなければブラウザのコンソール(F12)のエラーを添えて報告
