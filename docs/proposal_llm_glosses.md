# 提案: 語義説明文のLLM生成((c)ハイブリッドへの移行。実装は承認後)

作成日: 2026-08-13
背景: phase2b_ui_review.md 修正4。senses.yaml の手キュレーションは5語のみで、UI必須項目「この分野での意味(英語)/一般・分野の日本語」が大半の語で「未生成」。Phase 0 の (a)完全静的では表示要件を満たせないことが実地で判明した。

## 不変の原則(発注者指示)

- **レベル判定・順位付けは静的アルゴリズムのまま。LLMは一切関与しない**
- LLMの仕事は**説明文の文面生成のみ**
- 生成物はキャッシュし、同じ語を二度生成しない
- `data/senses.yaml`(手キュレーション)は常に生成物より**優先**(上書き)

## 案A(推奨): ビルド時全語プリベイク

**発想の転換: 頻出語をキャッシュするのではなく、収載語すべてを一度だけビルド時に生成して vocab_table に焼き込む。** 実行時は静的配信のままなので、**Phase 0 の「(a)完全静的」の枠内に収まり、ユーザーのAPIキーが不要になる**。

| 項目 | 内容 |
|---|---|
| 生成対象 | L3 約2,500語 + L2 約5,000語(まず L3 のみでも可) |
| 生成内容 | 語ごとに: domainSense(英語・短句)/ contrast(一行対比)/ jaGeneral / ja。多義が明白な語は senses 複数(mass 型) |
| 入力に渡すもの | 語 + レベル + collGeneral / collField(判定層の副産物が文脈証拠になる)+ 分野(cs.RO+cs.LG)+ 対象読者(制御出身) |
| モデル | Claude Sonnet 5(バッチAPI)。品質優先。定型生成なので Haiku 4.5 でも可 |
| **コスト見積もり** | 1語あたり入力≈300tok / 出力≈150tok。L3 2,500語 ≈ 入力0.75M+出力0.38M tok。Sonnet 5($3/$15 per MTok)≈ **$8、バッチAPI(50%off)で≈$4**。Haiku 4.5 なら ≈$1。L2込みでも3倍(一回きり) |
| 実行 | 発注者のローカルで `ANTHROPIC_API_KEY=... npm run bake:glosses`(pipeline スクリプト)。キャッシュは `data/glosses_generated.yaml` にコミット → 以後のビルドはAPI不要 |
| サイズ影響 | +150〜250バイト/語 ≈ +600KB〜1.2MB(gzip後は1/4程度)。上限5MB内。必要なら日本語のみ遅延ロード分割 |
| オフライン | **常時完全動作**(実行時APIなし) |
| APIキー | 実行時不要。ビルド時のみ発注者の手元で使用 |
| コーパス更新時 | 新規収載語の**差分のみ**生成(キャッシュヒットで既存語コストゼロ) |

### 品質管理
- プロンプトで「一行で刺さる対比」を強制(curriculum / disturbance / actor の発注者例文をfew-shotに使用。正確さより分かりやすさ優先の指示)
- 検証: 正解セット20語+heldout の生成結果を発注者が目視(この30語で品質が出れば残りも信用する、という抜き取り検査)
- senses.yaml の手書きが常に優先。生成物に誤りを見つけたら senses.yaml に正しい記述を書けば上書きされる(既存の運用と同一)

## 案B: 実行時オンデマンド生成(ユーザーAPIキー)

- ブラウザから Anthropic API を直接叩き、結果を localStorage にキャッシュ
- 利点: 事前生成なしで任意の語に対応(L1a 由来の未収載語にも将来対応可)
- 欠点: APIキーの入力・保管が必要(localStorage 保管はXSS耐性が低い)/ オフライン時は未キャッシュ語が出ない / CORS 制約(Anthropic API は `anthropic-dangerous-direct-browser-access` ヘッダで直接呼べるが、キー漏えいリスクをユーザーが負う)/ 初回読書のレイテンシ
- コスト: 従量(1文書あたり数円未満)だが管理はユーザー任せ

## 推奨

**案A**。理由: (1) Phase 0 の静的原則を実行時に維持したまま表示要件を満たす、(2) コストが一回きり数ドルで、キャッシュ運用(発注者要求)がファイルコミットという最も単純な形になる、(3) オフライン・APIキー問題が発生しない。案B は「読んでいて未収載語に出会ったとき」の将来拡張として温存(その時点で本当の (c)ハイブリッドになる)。

## 承認時に決めてほしいこと

1. 案A / 案B / 併用のどれで進めるか
2. 生成範囲: L3のみ($4)か L3+L2($12程度)か
3. モデル: Sonnet 5(品質)か Haiku 4.5(1/5のコスト)か — 抜き取り検査で品質不足なら上位モデルで再生成すればよいので、Haiku 開始→不足なら Sonnet も合理的
