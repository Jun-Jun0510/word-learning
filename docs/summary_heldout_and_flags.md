## 2. ⚑フラグ診断(発見1への回答)

まず訂正: ⚑は**10語**(発注者指摘が正。データは常に10で、報告メッセージ作成時の数え間違い)。

### ⚑が実際に拾っているもの(採点済み50語での内訳)

⚑の発火源は2系統: (i) topic-flagged ルート(fk≥θk かつ厳格な語義ルート不成立)5語、(ii) freq+sense の rgRel弱 5語。採点結果との突合:

| ⚑語 | 発火源 | 採点 |
|---|---|---|
| human | topic-flagged | 話題語 ✓ |
| success / camera | freq+sense弱rg | 話題語 ✓ |
| approach / challenge | topic-flagged | 学術一般 ✗ |
| demonstrate | freq+sense弱rg | 学術一般 ✗ |
| feature / map | topic-flagged | **L3妥当 ✗** |
| online / prior | freq+sense弱rg | **L3妥当 ✗** |

### 診断

⚑の実体は「話題語」ではなく **「C頻出 かつ 一般隣人消失(rgRel)の証拠が弱い語」**。rgRel が弱くなる原因は3系統あり、⚑はそれを区別できていない:

- (a) 真の話題語(語義不変なので一般隣人が C でも残る): human, camera — 意図どおり
- (b) 学術文体語(B にも C にも頻出): approach, challenge, demonstrate — kBA が高い群
- (c) **C内で一般語義と分野語義が併存する多義語**: prior(「prior work」の形容詞用法が一般隣人を保存するため rg=0.069)、feature、map — **これは最も危険なL3であり、⚑を付けるのは逆効果**。mass で見た分野内多義の問題と同根

### 提案(2b実装前の判断材料。パラメータ凍結中につき実装はしない)

1. **「話題語疑い」としての⚑表示は保留を推奨**(適合率30%では信号として機能しない。発注者の保留判断オプションに該当)
2. 代替案(2bで判断): (b) は kBA≥θb で機械的に分離可能。(a) と (c) の分離は rgRel では原理的に不可(まさに (c) だから rg が低い)。表示するなら中立ラベル「自動判定の確信度低」に格下げする案
3. サンプル10語での診断であり、断定はしない(過適合サイクルの教訓)
