# 競合調査レポート (Phase 0) — requirements-agent

作成日: 2026-08-13
担当: requirements-agent(競合調査)

## 結論(先出し)

「読者にとっての危険度(L3=見た目日常語・分野で特殊語義)」を軸にした読む前予習ツールは、**消費者向けには実質存在しない**。L3的な発想は学術言語学(polysemy検出研究)にはあるが、製品化されていない。**独自性は成立する**。ただしリスクは「独自性の核=L3検出の技術的実現難度」に集中している。

## 2. 各ツール詳細

### Readlang
1. Web上の任意テキストをクリック/ドラッグで即翻訳し、その語をSRSフラッシュカード化する多読補助ツール。
2. 難易度=「自動可読性指数(ARI)」+「上位2000頻度語カバー率」の複合。語自体の優先度は頻度リスト基準。
3. 予習は非対応。読みながら未知語を潰す設計。
4. 分野特化語義は扱わない。「日常語が専門で別義」の警告はない。
5. 無料プラン+Premium(月$5前後)。ブラウザ/Web。
6. 差分: 本プロダクトは「読む前」に文書全体を解析しL3を抽出する点、翻訳ではなく「誤読しやすい語の語義注意」を出す点が異なる。
- https://blog.readlang.com/2016/01/21/the-readlang-method-for-foreign-language-vocabulary.html
- https://forum.readlang.com/t/how-does-readlang-know-the-difficulty-of-a-text/37

### LingQ
1. 30+言語の多読・多聴プラットフォーム。既知語数を成長指標として可視化。
2. 語を「既知/未知(LingQ)」でユーザーが二値管理。レッスンは6レベル、未知語%を表示。
3. ユーザーの既知/未知履歴で未知語ハイライトは「読者にとっての」個別化に近いが、「知ってるつもりで誤読する語」は捉えない。
4. 分野特化語義は非対応。
5. 無料/Premium $12.99月・$107.88年。Web/アプリ。自前コンテンツimport可。
6. 差分: LingQの個別化は「未知語ベース」。本プロダクトの核心は「既知語だが分野で別義=危険語」で、LingQのモデルでは既知扱いされ素通りする領域を狙う。**ここが最大の差別化点。**
- https://www.lingq.com/blog/lingq-free-vs-premium/
- https://www.alllanguageresources.com/lingq-review/

### Anki
1. 汎用SRS暗記アプリ。難易度判定なし。特定文書と非連動。
2. 差分: Ankiは「覚える段階」の道具。本プロダクトは「何を覚えるべきか(文書からL3抽出)」の前段。**補完関係で、抽出結果のAnkiエクスポートは連携アイデアになる。**
- https://refold.la/roadmap/library/learning-words-with-anki

### Yomitan (旧Yomichan)
1. Shift+ホバーで辞書ポップアップを出すブラウザ拡張(20+言語)。
2. 頻度データ等を「表示」するが難易度判定はしない。複数辞書同時参照。
3. L3に最も技術的に近い: 複数辞書で1語の複数語義を列挙できるが、「この文書/この分野でどの語義が危険か」の判定・優先度付けは自動でない。
4. 差分: Yomitanは「引ける辞書」、本プロダクトは「引くべき危険語を先に指摘する」。方向が逆。AnkiConnect連携の思想は参考になる。
- https://yomitan.wiki/

### DeepL
1. ニューラル機械翻訳。予習非対応。「翻訳せずに読む」という本プロダクトの目的の対極。
2. 用語集(glossary)は「訳語の一貫性」であってL3(誤読リスク検出)ではない。
3. 差分: 競合というより「読者が今使っている代替手段」。本プロダクトは「DeepLに頼らず原文を読めるようにする予習」で、DeepLの利用頻度を下げるのが価値。
- https://www.eesel.ai/blog/deepl-pricing

### Vocabulary Profiler / Compleat Lexical Tutor (Tom Cobb)
1. テキストを貼ると語彙を頻度帯(K1/K2/AWL/オフリスト)に分類し色分けする語彙分析ツール。
2. Laufer & NationのLexical Frequency Profile方式。純粋に一般頻度リスト照合。
3. 発想が最も近い先行研究系ツールだが、「offList(頻度外)」に専門語が落ちる一方、kernel/regular等は**K1に分類され危険と見なされない** ← 既存プロファイラの盲点であり本プロダクトの狙い目。
- https://www.lextutor.ca/vp/
- https://www.tesl-ej.org/ej31/m2.html

### AntWordProfiler (Laurence Anthony)
1. LexTutorのデスクトップ版相当。PDF/docx/txt対応、色分け、カスタムリスト読込可。
2. カスタムリスト機能=「分野別危険語リスト」を自作すれば近いことは可能 → 機能アイデアの参考。
3. 差分: エンジンは強力だが「一般頻度の可視化」止まり。自動L3判定・学習者向けUI・10〜15分予習体験はない。
- https://www.laurenceanthony.net/software/antwordprofiler/

### AWL Highlighter (EAPFoundation等)
1. Academic Word List(570語族)を強調表示。固定リスト照合のみ。
2. 差分: 「文書から重要語を抽出して事前提示」という体験の骨格は近いが、リストが固定・汎用で読者/分野に非適応。
- https://www.eapfoundation.com/vocab/academic/highlighter/

### WordUp
1. 25,000語を実用頻度順にランクしたAI英単語アプリ。文書非連動、予習非対応。無関係に近い。
- https://www.wordupapp.co/

### (参考)学術研究: Interdisciplinary Polysemy Detection
- L3そのものの学術的裏付け。「同一語が分野で異なる語義を持つ」を頻度・分散・キーネス・共起で自動検出する研究が存在。
- 製品化されておらず、本プロダクトが「研究で有効性が示された概念の初の消費者向け実装」を名乗れる根拠になる。
- https://www.sciencedirect.com/science/article/abs/pii/S1475158524001176
- https://arxiv.org/pdf/2506.02758 (LLMによる語彙難易度評価の先行例)

## 3. 差別化分析

**「読者にとっての危険度(L3)」をやっている消費者向け製品は存在しない。**

- 「難易度判定」系(Readlang, LexTutor, AntWordProfiler, AWL Highlighter, WordUp)はすべて**一般頻度**が基準。kernel/regular/tight等は高頻度=易しいと分類され、危険フラグが立たない。既存全ツール共通の盲点。
- 「個別化」系(LingQ)は**未知語ベース**。「知ってるつもりで誤読する語」は既知扱いで素通り。L3の定義とちょうど逆の領域を残す。
- 「複数語義参照」系(Yomitan, 辞書)は語義を**列挙できるが判定しない**。
- 唯一概念的に一致するのは**学術のpolysemy検出研究**だが、製品化されていない。

部分的に近い順: (1) LexTutor/AntWordProfilerのカスタムリスト機能 → (2) LingQの読者別未知語ハイライト → (3) Yomitanの多辞書語義列挙。

## 4. 競合から学べる機能・UXアイデア

1. **危険語カバー率の可視化**(LingQ・LexTutor): 「この文書のあなたの危険語カバー率X%」「予習でY%潰せる」を予習前後で数値化。
2. **Anki/CSVエクスポート**(Anki・Yomitan連携文化): 危険語だけを既存SRSに送れると定着が上がる。サーバー不要で実装可。
3. **色分けオーバーレイ**(AntWordProfiler・AWL Highlighter): 原文上でL3語を危険度別に色ハイライトし、クリックで「日常の意味 vs この分野の意味」を対比表示。
4. **ミスコンセプション先回り型の対比カード**(Readlang・Yomitan): 「あなたはこの語をXだと思っているが、この文書ではY」という一般語義→分野語義の対比学習。
5. **危険度で予習語を絞る**: 全未知語を出すと10〜15分に収まらない。危険度ランク上位N語に絞る「予習の要約」UX。

## 5. 結論(忖度なし)

**独自性は成立する。** 既存ツールの共通盲点(頻度=易しさ)を正面から突いており、コンセプトとして筋が良い。ブラウザ完結/GitHub Pagesも先例からブラウザ内処理で十分成立する。

**ただし、独自性の核こそが最大のリスク:**

1. **L3自動検出の技術的難度(最重要)**: 「kernel が数学/CS/種子で別義」の判定には (a)分野判定 + (b)語義曖昧性解消 + (c)「日常語かつ分野別義」の絞り込み が必要。頻度リスト照合では原理的に不可能で、辞書の複数語義データかLLMが要る。品質が出せないと「ただの単語ハイライター」に転落する。**PoCでL3検出の精度をまず検証すべき。**
2. **「危険度」の正解が主観的**: 読者の既存知識に依存。初版は「分野別の典型的危険語」の固定的検出に留め、個別化は段階導入が現実的。
3. **予習習慣の定着ハードル**: 「読みながら」より心理的ハードルが高い可能性。誤読で失う時間>予習時間、という価値をUIで明示する必要。
4. **市場が狭い**: 研究者/エンジニア/学生のニッチ。個人開発・費用ゼロ前提とは整合的で妥当。

**要件定義への示唆: MVPの成否はL3検出エンジン一点に懸かる。** ここを最初に技術検証(PoC)し、周辺機能は既存ツールの枯れた手法を流用するリソース配分を推奨。
