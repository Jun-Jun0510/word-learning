最終更新: 2026-08-13
一次ソース: `project_brief.txt` / `docs/phase0_answers.md`(齟齬があれば phase0_answers.md が正)
関連: `docs/research_competitors.md`(競合調査)

## 1. プロダクト概要

英語の論文・技術記事を「翻訳せずに読む」ための事前単語学習アプリ。
読む前にテキストを読み込ませ、文書中の単語を「一般的な難易度」ではなく **その読者にとっての危険度** でレベル分けして提示し、10〜15分で予習できる状態にする。

競合調査の結論: この切り口(L3危険語)を持つ消費者向けツールは存在せず、独自性は成立する。一方、MVPの成否はL3検出エンジン一点に懸かる(詳細は `research_competitors.md`)。

## 2. 対象ユーザー(読者)

**ohatajun 本人に固定。**

- 制御系エンジニア。plant / gain / observer / regular(制御文脈)は既知
- 対象分野: **arXiv cs.RO + cs.LG を合わせて1分野**として扱う。eess.SY は非スコープ(既知側のため)
- 複数分野の切り替えは初期スコープ外
- 利用環境: PC + スマホ(iPhone)

## 3. ユーザーストーリー

1. **予習**: 読者として、読む予定の論文テキストを貼り付けると、危険度順(L3→L2)の単語リストが出て、10〜15分眺めるだけで読み始められる状態になりたい。
2. **誤読の先回り**: 読者として、L3語について「一般的な意味」と「この分野での意味」の対比を一行で見て、「知ってるつもり」の誤読を読む前に潰したい。
3. **蓄積**: 読者として、文書を読み込むたびに語が単語帳に蓄積され、known にした語は次回以降の予習リストから消えることで、使うほど予習が軽くなってほしい。
4. **振り返り**: 読者として、読了直後にL3語を見返して「正しい分野固有の意味で解釈できていたか」を自己採点し、記録したい。
5. **データ保全**: 読者として、蓄積した単語帳をJSONでエクスポート/インポートし、ブラウザデータが消えても資産を失いたくない。

## 4. 単語レベルの定義(二軸モデル)

**L1とL3は対立カテゴリではない。** 「一般英語で高頻度」という同じ入口から入る同一母集団を、分野側の挙動で割った結果である。実装は必ず「縦軸(一般頻度)で候補プールを作る → 横軸(分野でのズレ)で割る」の順序。**「L1除外」という工程は作らない。**「一般頻度の上位N語カット」という閾値方式は廃止。

### コーパス3本
- **A**: 一般英語コーパス(日常英語。wordfreq / SUBTLEX)
- **B**: 学術英語コーパス(分野横断の論文英語)
- **C**: 分野コーパス(arXiv cs.RO + cs.LG)

### 分類

| レベル | 定義 | 例 | 扱い |
|---|---|---|---|
| L1a | Aで高頻度、BでもCでも突出しない | the, take, house | 非表示(ただし保留、復活パスあり) |
| L1b | Aに対しBで突出、Cでは特に突出しない | denote, yield, respectively, hence, constitute, thereby | 「論文英語」層。単語帳モードのみ表示 |
| L3 | Aで高頻度だが、Cで分布・語義がズレる | kernel, sample, regular, tight, dense, sound, novel | **最優先** |
| L2 | Aで低頻度、Cで高頻度 | eigenvalue, holonomic | 中優先 |
| L4 | 略語・記号(平面外) | FOC, PMSM, MPC | Phase 3 |

L1b はB由来なので分野を問わず再利用でき、Cを切り替えても残る資産として扱う。

### L1a判定の検証要件(必須)
L1a判定はL3の取りこぼしを静かに生むため:
- L1aは破棄せず「保留」として中間データに全て残す
- 保留語のうちCで相対頻度が閾値を超えるものはL3候補に**復活**させるパスを通す
- デバッグ出力「L1aで落ちた語の上位N件」を目視確認できる形で出す(kernel / regular / sample / sound / plant / tight / dense が混ざっていれば閾値が誤り)
- 評価スクリプトは取りこぼしを「判定ロジックが落とした」「L1a判定が先に落とした」で必ず切り分けて報告する

## 5. 機能要件

### 5.1 入力
- **Phase 2: テキスト貼り付けのみ**
- Phase 3: PDF(pdf.js でブラウザ完結)、L4略語抽出
- 最後: URL取り込み(CORS proxyが要るため優先度を上げない)

### 5.2 抽出・分類
- レベル判定は**静的アルゴリズム**(ビルド時に事前計算した統計をJSONに焼き、実行時は引くだけ)。**LLMにレベル判定を投げるのは禁止**(精度測定可能性の確保。ここがアプリの中身)
- LLMの用途は語義説明の文面生成のみ、かつ Phase 2 は完全静的。説明の質の不足を確認できてから (c)ハイブリッドに拡張(順序厳守)
- **文書内出現回数で足切りしない**。1回しか出ない専門語も必ず出す。出現回数はソート補助と表示用のみ

### 5.3 表示(単語リストの各項目)
必須3つ:
1. その分野での意味(英語)
2. 一般的な意味との対比(L3の肝。一行で刺さること)
3. 文書内の実際の出現文を1つ

- 日本語訳はトグルで、**デフォルト非表示**(翻訳に頼らないのが目的)
- 出現回数は内部値として保持し、UIには小さく添える程度

### 5.4 UIモード(2モード。混ぜない)
- **予習モード**: 読む直前用。**L3 → L2 のみ**表示(L1bは出さない)。10〜15分で読み始められること。**L3は上位20語を表示上限**(調整可能なパラメータ。絞り順は score降順→文書内出現回数降順、削られた語は「もっと見る」で全展開可能。algorithm.md §3)。フラッシュカードは非スコープ、リストを眺めるだけ。各項目に1タップのステータス変更
- **単語帳モード**: 蓄積した語を後から見る。L3 / L2 / L1b 全部。レベル別・習得状況・出典文書でフィルタ可能

### 5.5 単語帳の蓄積(永続化)
- 文書を読み込むたびに語が永続DBに積まれる。同じ語が複数文書に出たら出典を配列で持ち出現回数を加算(重複エントリを作らない)
- ステータス3値: `new` / `learning` / `known`。1タップで変更
- known は予習モードから消えるが単語帳には残る(「使うほど予習が軽くなる」導線の本体)
- 保存は localStorage。**上限時の挙動を設計しておく**
- **JSONエクスポート/インポートは Phase 2 必須**(蓄積型にした時点でデータの価値が上がるため)
- データ構造はAnki向けCSV出力が可能な形にしておく(エクスポート機能自体は非スコープ)

### 5.6 読了後チェック画面
読了直後、その文書のL3語を見返して「読中に正しい分野固有の意味で解釈できていたか」を自己採点し記録するUI。成功指標の主指標を計測する装置であり、**最小版(L3語ごとに○/×を1タップ)を Phase 2c に含める**(これがないと主指標が計測不能になるため。リッチ化はPhase 3)。

## 6. 非機能要件

- ブラウザ完結、GitHub Pages でデプロイ(サーバー費用ゼロ)
- スマホ(iPhone)から使えること
- 配信する事前計算データ: **上限5MB、目標1MB以下**。頻度表そのものではなく事前計算の結果だけを配信。重い集計はビルド時にNodeスクリプトで実行
- 個人開発(平日夜と週末)。1機能でも動くことを最優先。過剰設計しない

## 7. 技術スタック

- React + Vite + TypeScript + Tailwind CSS
- 状態管理ライブラリは入れない(useState で足りるうちは足りる)
- 選定理由と初期セットアップ手順を docs に残す(Phase 2 で `docs/setup_frontend.md` を作成)

## 8. スコープ / 非スコープ

### Phase 2(プロトタイプ)スコープ — 3段に分割して順に動かす

個人開発の時間制約(平日夜・週末)に対しPhase 2一括は過大なため、各段が単独で「動く・測れる」状態になるよう分割する。**2a のゲート通過までUIに進まない。**

- **Phase 2a: 判定エンジン+評価(UIなし)**
  - コーパス調達(A頻度/A共起/B/C)と前処理、二軸分類パイプライン(L1a保留・デバッグ出力含む)
  - 評価スクリプト(正解セット20語+負例、再現率・適合率ゲート、取りこぼし切り分けレポート、話題語混入率)
  - **ゲート: 再現率≥70% かつ precision@50≥60%**(algorithm.md §6-2)。未達なら増強パスを回し、ここでレビュー
  - 完了報告にはゲート数値に加え、L1a落ち上位N件・話題語疑いプール上位N件・取りこぼし4段切り分け結果を必ず添える(Phase 1 承認条件)
- **Phase 2b: 最小UI**
  - テキスト貼り付け → レベル分けされた単語リスト(L3→L2、単一画面)
  - arXiv abstract 3本程度での実地検証とレビュー
- **Phase 2c: 蓄積と保全**
  - 予習モード / 単語帳モード の2モード分離(3値ステータス、フィルタ)
  - localStorage 永続化 + JSONエクスポート/インポート
  - 読了後チェック最小版(L3語の○/×1タップ採点)

### Phase 3 以降
- PDF入力(pdf.js)
- L4 略語・記号抽出
- 読了後チェック画面のリッチ化(最小版は Phase 2c)
- LLMによる語義説明生成((c)ハイブリッド。静的説明の質不足を確認してから)

### 非スコープ
- 全文翻訳
- フラッシュカード/SRS機能
- Ankiエクスポート機能の実装(データ構造の互換性のみ担保)
- 複数分野の切り替え、eess.SY
- URL取り込み(最後まで優先度を上げない)
- 状態管理ライブラリ、サーバーサイド構成

## 9. 成功指標

**最終目的**: 対象論文をDeepL等に丸投げせず、英語のまま最後まで読み切れること。

| 種別 | 指標 | 目標 |
|---|---|---|
| 主指標 | 読了直後、提示されたL3語の「読中に正しい分野固有の意味で解釈できていたか」自己採点 | 正答率80%以上 |
| 副指標 | 「丸投げせずに読み切れた = Yes」 | 論文3本連続 |
| アルゴリズム指標(再現率) | 手作り正解セット20語に対するL3検出の再現率 | 70%以上 |
| アルゴリズム指標(適合率) | L3判定スコア上位50語の手動採点 precision@50(話題語混入率も併記) | 60%以上(暫定) |

**アンチ指標**: 「読中に辞書を引く回数」は指標にしない。予習が効くと誤読への気づきが増え、確認回数はむしろ増えうる。減るべきは「引かずに誤読する回数」。

## 10. 主要リスク

1. **L3自動検出の精度**(最重要): 頻度比だけでは「頻度は変わらず語義だけ変わる語」が漏れ、逆に共起分布差だけでは「語義不変の話題語(robot, controller)」が混入する。手法選定と話題語ガードは `docs/algorithm.md` で規定し、Phase 2a のPoCで最初に話題語混入率を実測する
2. **語義説明の質**: Phase 2 は静的データのみ。不足なら (c)ハイブリッドへ(順序厳守)
3. **予習習慣の定着**: 10〜15分で終わる体験に絞る(L3→L2のみ、リスト閲覧のみ)
4. **蓄積データの喪失**: JSONエクスポート/インポートを Phase 2 必須とすることで対処
