## 第3信号への投資 → 保留。判断の前提が変わった

条件「C拡充後も混入するなら第3信号を検討」は確かに成立したが、
その前に評価基準そのものを見直す。

理由: 適合率の誤りと再現率の誤りは価値が非対称であり、
これを Phase 1 の precision@50 ≥ 60% は考慮していなかった。

- 話題語の混入(robot, trajectory, motion): ユーザーが1タップで known にでき、
  既知語ステータスで永久に消える。ドメインの話題語彙は有限かつ毎回同じ語が出るため、
  数本読めば飽和して消滅する。**自己修復する誤り**
- L3の取りこぼし(support, head, collapse): ユーザーは気づけない。
  出てこない語は学べない。**永久に残る誤り**

したがって今回の修正(適合率を再現率で買う)は方向が逆。
検証セット 18/20→14/20、sense_shift 9/10→7/10 の劣化は、
話題語16語の混入より重い損失である。

## 方針転換: 再現率優先に戻せ

1. topic-suspect ガードの誤爆を最優先で潰せ。
   support / head / augmentation / model / agent を落としている経路が
   現在の主要な損失源。ガードを弱めて再現率を戻し、適合率の低下は許容する。
2. θrr = 0.5 の採用を再考しろ。hard 0.524 / primitive 0.502 が
   閾値ぎりぎりというリスク記録は正しい。もっと緩い値で再現率を回復させろ。
3. ジャーゴンガード delta > 0.42 も同様。L2 降格自体は正しいが、
   閾値が採点済み50語から導出されている点に注意(後述)。

## ゲート基準の変更

precision@50 ≥ 60% を撤回する。新基準:
  - 必須: 検証セット再現率 18/20 以上、sense_shift 9/10 以上を回復すること
  - 目標: precision@50 ≥ 35%(話題語は自己修復する前提で緩和)
  - 追加: 話題語と判定された語を L3 リスト内で区別表示できること(実装済みの⚑を拡張)

## 過適合サイクルの警告(3周目)

θrr スイープも delta=0.42 も、採点済み50語に対して最適化されている。
20語で起きたことと同じ構造を50語で繰り返している。
この50語はもう検証セットであり、汎化性能を示さない。

対応:
- 新しい precision@50 リストは、既に採点した50語と重複しない語で構成しろ。
  重複が避けられないなら重複語を明示しろ。
- 閾値を採点済みデータから導出した箇所を algorithm.md に全て列挙しろ。
  どのパラメータが何にフィットしているか一覧で見えるようにすること。
